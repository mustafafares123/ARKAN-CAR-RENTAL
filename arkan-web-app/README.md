# ARKAN CO. – RENT A CAR | Web starter

هذه نسخة أولية عملية قابلة للتشغيل محلياً، ومهيأة للانتقال إلى استضافة مؤقتة. الواجهة متجاوبة للكمبيوتر والهاتف وتدعم العربية والإنجليزية.

## ما الذي يعمل الآن؟
- لوحة تحكم ومؤشرات أسطول تجريبية.
- أقسام السيارات والعملاء والحجوزات والعقود والصندوق والصيانة وأجهزة GPS والمخالفات.
- إضافة سجلات والبحث فيها داخل المتصفح.
- في قسم السيارات: تعديل السجل وحذفه ورفع صورة ومعاينتها، مع حقول اللون وناقل الحركة ونوع الوقود.
- حفظ تجريبي داخل المتصفح الحالي (`localStorage`)؛ صور السيارات تُضغط إلى JPEG قبل حفظها محلياً.
- تبديل العربية/الإنجليزية.
- تصميم قابل للتثبيت كتطبيق ويب على الهاتف (PWA manifest).

## تنبيه مهم
الوضع الحالي **تجريبي محلي**: البيانات تبقى في المتصفح والجهاز نفسه فقط، ولا تتزامن بين الموظفين أو الأجهزة. لا تدخل بيانات هويات أو جوازات أو عقود أو بيانات مالية حقيقية قبل اكتمال المصادقة وربط قاعدة البيانات واختبار الصلاحيات والنسخ الاحتياطي.

وجود متغيرات Supabase أو نجاح نشر Vercel لا يعني أن التطبيق يزامن البيانات. وظائف تعديل/حذف السيارات ورفع صورها في الواجهة الحالية تعمل محلياً داخل المتصفح فقط، ولا تنفّذ بعد عمليات CRUD على جدول `cars` أو رفع الصور إلى Supabase Storage. لا تعتبرها نسخة تشغيل سحابي متعددة الأجهزة. كما لا تتوفر شاشة تسجيل دخول/إنشاء حساب بعد. شاشة GPS لا تتصل بجهاز فعلي بعد؛ يلزم جهاز ومزود يدعم API أو بروتوكولاً متوافقاً، مع حفظ أسرار الربط على الخادم. المخالفات الرسمية لا تُجلب تلقائياً إلا بوجود تكامل رسمي مع الجهة المختصة.

## شروط قبول العملاء وتذكير SMS

- ملف `supabase/customer_compliance.sql` يضيف تاريخ الميلاد، تاريخ إصدار الرخصة وانتهائها، ومسارات صور الهوية والرخصة.
- صورة الهوية الأمامية والخلفية إلزامية في شاشة العملاء. العمر يحسب من تاريخ الميلاد ويجب ألا يقل عن 24 سنة.
- يجب أن تكون مدة امتلاك الرخصة **أكثر من سنتين كاملتين**، وأن تكون الرخصة غير منتهية.
- صور الوثائق تحفظ في bucket خاص `arkan-private` ولا تنشأ لها روابط عامة.
- ينشئ ترحيل SQL جدول `sms_reminders` وجدولة تذكير قبل موعد إعادة السيارة بساعتين (توقيت فلسطين)، عند إضافة الحجز أو تعديل موعد الإعادة.
- **إرسال SMS الفعلي لم يُفعّل بعد**: يلزم اختيار مزود SMS يدعم أرقام فلسطين، إضافة بيانات اعتماده بشكل سري في الخادم، وإعداد عامل مجدول يقرأ الرسائل المستحقة ويرسلها ويحدّث حالة الرسالة. لا تضع مفاتيح المزود في متغيرات `NEXT_PUBLIC_*`.

شغّل `supabase/customer_compliance.sql` بعد `schema.sql` و`cloud_cars.sql`. لا ترفع صور هويات حقيقية قبل اختبار إعدادات الدخول وصلاحيات الوصول والنسخ الاحتياطي.

## تفعيل إدارة السيارات السحابية

1. افتح مشروع Supabase الصحيح ثم SQL Editor.
2. إذا لم تكن الجداول موجودة، شغّل `supabase/schema.sql` أولاً.
3. شغّل بعدها الملف `supabase/cloud_cars.sql` كاملاً؛ ينشئ إجراء إنشاء الشركة وحقول السيارات ومساحة صور خاصة وسياسات التخزين.
4. في Supabase Authentication، فعّل وسيلة Email. أنشئ حساباً من شاشة ARKAN أو سجّل الدخول بحساب موجود. إذا كان تأكيد البريد مفعلاً، افتح رسالة التأكيد أولاً.
5. في Vercel > Project Settings > Environment Variables أضف:
   - `NEXT_PUBLIC_SUPABASE_URL` = رابط مشروع Supabase.
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = مفتاح anon / publishable فقط.
6. أعد نشر المشروع بعد حفظ المتغيرات، ثم افتح رابط الإنتاج وسجّل الدخول.

بعد تسجيل الدخول، قسم السيارات يقرأ ويضيف ويعدّل ويحذف سجلات جدول `cars` ويرفع الصور إلى bucket خاص باسم `arkan-private`. روابط الصور مؤقتة وموقعة، ولا تجعل bucket عاماً.

**تنبيه:** هذا الربط السحابي مطبّق حالياً على قسم السيارات فقط. بقية الأقسام لا تزال محلية. لا تضع مفتاح `service_role` في متغير يبدأ بـ `NEXT_PUBLIC_` ولا تشاركه في المحادثة. لا تدخل بيانات عملاء حقيقية قبل اختبار صلاحيات الحساب والنسخ الاحتياطي.
 
## 1) المتطلبات
- كمبيوتر Windows / macOS.
- تثبيت Node.js إصدار 20 أو أحدث من https://nodejs.org
- تثبيت VS Code اختياري.
- اتصال إنترنت لتنزيل الحزم.

## 2) تشغيل البرنامج على الكمبيوتر
1. فك ضغط `ARKAN_WEB_STARTER.zip`.
2. افتح المجلد `arkan-web-app` في VS Code.
3. افتح Terminal داخل المجلد.
4. نفّذ:

```bash
npm install
npm run dev
```

5. افتح هذا العنوان في Chrome أو Edge:

```text
http://localhost:3000
```

لإيقافه اضغط `Ctrl + C` في نافذة Terminal.

## 3) رفعه كرابط مؤقت على الإنترنت
1. اربط مستودع GitHub بالمشروع في https://vercel.com.
2. اختر إعدادات Next.js الافتراضية ثم Deploy.
3. استخدم رابط Vercel الذي يظهر بعد نجاح النشر.

نجاح البناء أو ظهور رابط عام لا يثبت أن تسجيل الدخول أو مزامنة البيانات أو الصلاحيات تعمل. لا تُدخل بيانات عملاء حقيقية في النسخة التجريبية.

## 4) إعداد قاعدة Supabase (تهيئة فقط؛ لا تفعّل التشغيل التجاري بعد)
1. أنشئ مشروعاً خاصاً في https://supabase.com.
2. خذ نسخة احتياطية أولاً إذا كان المشروع يحتوي بيانات.
3. افتح SQL Editor وشغّل `supabase/schema.sql` مرة واحدة لإنشاء الجداول والسياسات الأولية.
4. **بعد نجاح الخطوة السابقة، شغّل `supabase/production_upgrade.sql` أيضاً. لا تتجاوز هذه الخطوة.** ملف الترقية ينشئ دوال عضوية الشركة وإنشاء/استرجاع شركة المالك، ويستبدل سياسات العضوية العامة بسياسات تعتمد الأدوار. تشغيل `schema.sql` وحده يترك سياسات أولية أوسع من سياسات الترقية.
5. راجع نتائج SQL وتأكد من عدم وجود أخطاء قبل الانتقال للخطوة التالية.
6. من Project Settings → API انسخ Project URL و anon/public key فقط.
7. أنشئ ملف `.env.local` في جذر المشروع بناءً على `.env.example`، وأضف:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

8. أعد تشغيل التطبيق.

**مهم:** هذه الخطوات تهيئ قاعدة البيانات فقط. التطبيق الحالي لم يكتمل فيه تسجيل الدخول ولا إنشاء عضوية المالك من الواجهة ولا مزامنة السيارات مع جدول `cars`. لذلك لا تعتبر إضافة المفاتيح أو تشغيل SQL دليلاً على أن التطبيق أصبح سحابياً، ولا تستخدمه لتشغيل الشركة قبل تنفيذ واختبار الربط.

## 5) بيانات الشركة والأمان
- استخدم حساباً منفصلاً لكل موظف، ولا تشارك كلمة مرور واحدة.
- لا تنشئ عضويات الموظفين أو تغيّر أدوارهم من المتصفح بصلاحيات مرتفعة؛ يجب أن يتم ذلك من مسار موثوق.
- خزّن صور الهويات والعقود في Storage خاص (Private bucket) مع روابط مؤقتة.
- لا تضع `service_role` key في متغير يبدأ بـ `NEXT_PUBLIC_` أو في كود المتصفح أو مستودع GitHub.
- فعّل النسخ الاحتياطية واختبر استعادة البيانات.
- اختبر عزل الشركات وصلاحيات كل دور بحسابات تجريبية منفصلة قبل إدخال بيانات حقيقية.

## 6) مراحل التطوير المقترحة
1. إضافة تسجيل الدخول وإنشاء حساب المالك وربطه بالشركة.
2. ربط السيارات بقراءة/إضافة/تعديل/حذف آمنة في Supabase واختبارها من جهازين.
3. ربط العملاء والحجوزات والعقود ومنع تعارض مواعيد السيارات.
4. تطوير التسليم والاستلام وتصوير الأضرار والعقود PDF.
5. دفتر الصندوق والعملات وأسعار الصرف والتقارير المحاسبية.
6. الصلاحيات وسجل التدقيق والفروع.
7. ربط مزود GPS عبر API بعد اختيار الجهاز والمزود، ثم WhatsApp والتنبيهات وبوابة العملاء والتحليلات.

يجب أن تدعم واجهة النظام والعقود العربية والإنجليزية بالكامل، مع اتجاه RTL للعربية وLTR للإنجليزية.

## 7) الملفات المهمة
- `app/page.tsx`: الواجهة والمنطق الأولي.
- `app/globals.css`: التصميم المتجاوب.
- `supabase/schema.sql`: مخطط قاعدة البيانات والسياسات الأولية.
- `supabase/production_upgrade.sql`: ترقية الصلاحيات ودوال الشركة والتخزين الخاص.
- `.env.example`: أسماء إعدادات الربط المطلوبة.
