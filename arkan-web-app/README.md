# ARKAN CO. – RENT A CAR | Web starter

## تحديث شروط التأجير وبيانات الاتصال
- رقم الهاتف الأساسي محفوظ في خانته، ويمكن إضافة عدة أرقام اختيارية في خانة الأرقام الإضافية؛ افصل بينها بفاصلة أو اكتب كل رقم في سطر.
- يمنع نموذج العميل حفظ الملف إذا لم تُرفق صورة الهوية الأمامية والخلفية، أو كان العمر أقل من 24 سنة، أو لم تمر أكثر من سنتين كاملتين على إصدار الرخصة، أو كانت الرخصة منتهية.
- يمنع نموذج الحجز والعقد محلياً العميل غير المسجل أو الذي لا يستوفي شروط العمر والرخصة.
- ملف supabase/customer_compliance.sql يضيف فحصاً على مستوى قاعدة البيانات عند إنشاء/تعديل الحجز والعقد، ويعيد فحص الرخصة عند تحديث العقد (بما في ذلك تغييرات الحالة التي تستخدمها عملية التسليم). يجب أن يتضمن سجل الحجز/العقد customer_id وcompany_id حتى يعمل المنع على الخادم.
- لا يزال ربط الحجوزات والعقود بالواجهة السحابية غير مكتمل؛ لذلك فحص الواجهة في هذين القسمين محلي حالياً. لا تعتبر هذه النسخة جاهزة للتشغيل التجاري قبل إكمال ذلك واختباره.


هذه نسخة أولية عملية قابلة للتشغيل محلياً، ومهيأة للانتقال إلى استضافة مؤقتة. الواجهة متجاوبة للكمبيوتر والهاتف وتدعم العربية والإنجليزية.

## بدء مساحة عمل نظيفة وحماية البيانات

- تبدأ النسخ الجديدة بقوائم سيارات وعملاء فارغة؛ لا تُنشأ سيارات أو أسماء عملاء تجريبية تلقائياً.
- لا يحذف هذا التحديث بيانات `localStorage` الموجودة أو سجلات Supabase أو صور Storage. تُحمّل البيانات المحفوظة سابقاً كالمعتاد.
- إذا كانت هناك بيانات تجريبية قديمة محفوظة مسبقاً في متصفحك، فلن يحذفها هذا التحديث تلقائياً؛ راجعها يدوياً قبل حذف أي سجل حتى لا تفقد بيانات حقيقية.

## ما الذي يعمل الآن؟
- لوحة تحكم ومؤشرات أسطول تجريبية.
- أقسام السيارات والعملاء والحجوزات والعقود والصندوق والصيانة وأجهزة GPS والمخالفات.
- إضافة سجلات والبحث فيها داخل المتصفح.
- في قسم السيارات: تعديل السجل وحذفه ورفع صورة ومعاينتها، مع حقول اللون وناقل الحركة ونوع الوقود.
- حفظ تجريبي داخل المتصفح الحالي (`localStorage`)؛ صور السيارات تُضغط إلى JPEG قبل حفظها محلياً.
- تبديل العربية/الإنجليزية.
- تصميم قابل للتثبيت كتطبيق ويب على الهاتف (PWA manifest).

## تنبيه مهم
الوضع الحالي **تجريبي محلي**: البيانات تبقى في المتصفح والجهاز نفسه فقط، ولا تتزامن بين الموظفين أو الأجهزة. لا تدخل بيانات هويات أو جوازات أو عقود أو بيانات مالية حقيقية قبل اكتمال المصادقة وربط قاعدة البيانات واختبار الصلاحيات والنسخ الاحتياطي.

وجود متغيرات Supabase أو نجاح نشر Vercel لا يعني أن التطبيق يزامن البيانات. وظائف تعديل/حذف السيارات ورفع صورها في الواجهة الحالية تعمل محلياً داخل المتصفح فقط، ولا تنفّذ بعد عمليات CRUD على جدول `cars` أو رفع الصور إلى Supabase Storage. لا تعتبرها نسخة تشغيل سحابي متعددة الأجهزة. كما لا تتوفر شاشة تسجيل دخول/إنشاء حساب بعد. شاشة GPS لا تتصل بجهاز فعلي بعد؛ يلزم جهاز ومزود يدعم API أو بروتوكولاً متوافقاً، مع حفظ أسرار الربط على الخادم. المخالفات الرسمية لا تُجلب تلقائياً إلا بوجود تكامل رسمي مع الجهة المختصة.

## شروط قبول العملاء وتذكير SMS

- ملف `supabase/customer_compliance.sql` يضيف تاريخ الميلاد، تاريخ إصدار الرخصة وانتهائها، ومسارات صور الهوية والرخصة.
- صورة الهوية الأمامية والخلفية إلزامية في شاشة العملاء. العمر يحسب من تاريخ الميلاد ويجب ألا يقل عن 24 سنة.
- يجب أن تكون مدة امتلاك الرخصة **أكثر من سنتين كاملتين**، وأن تكون الرخصة غير منتهية.
- صور الوثائق تحفظ في bucket خاص `arkan-private` ولا تنشأ لها روابط عامة.
- ينشئ ترحيل SQL جدول `sms_reminders` وجدولة تذكير قبل موعد إعادة السيارة بساعتين (توقيت فلسطين)، عند إضافة الحجز أو تعديل موعد الإعادة.
- **إرسال SMS الفعلي لم يُفعّل بعد**: يلزم اختيار مزود SMS يدعم أرقام فلسطين، إضافة بيانات اعتماده بشكل سري في الخادم، وإعداد عامل مجدول يقرأ الرسائل المستحقة ويرسلها ويحدّث حالة الرسالة. لا تضع مفاتيح المزود في متغيرات `NEXT_PUBLIC_*`.

شغّل `supabase/customer_compliance.sql` بعد `schema.sql` و`cloud_cars.sql`. لا ترفع صور هويات حقيقية قبل اختبار إعدادات الدخول وصلاحيات الوصول والنسخ الاحتياطي.

## تفعيل إدارة السيارات السحابية

1. افتح مشروع Supabase الصحيح ثم SQL Editor.
2. إذا لم تكن الجداول موجودة، شغّل `supabase/schema.sql` أولاً.
3. شغّل بعدها الملف `supabase/cloud_cars.sql` كاملاً؛ ينشئ إجراء إنشاء الشركة وحقول السيارات ومساحة صور خاصة وسياسات التخزين.
4. في Supabase Authentication، فعّل وسيلة Email. أنشئ حساباً من شاشة ARKAN أو سجّل الدخول بحساب موجود. إذا كان تأكيد البريد مفعلاً، افتح رسالة التأكيد أولاً.
5. في Vercel > Project Settings > Environment Variables أضف:
   - `NEXT_PUBLIC_SUPABASE_URL` = رابط مشروع Supabase.
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = مفتاح anon / publishable فقط.
6. أعد نشر المشروع بعد حفظ المتغيرات، ثم افتح رابط الإنتاج وسجّل الدخول.

بعد تسجيل الدخول، قسم السيارات يقرأ ويضيف ويعدّل ويحذف سجلات جدول `cars` ويرفع الصور إلى bucket خاص باسم `arkan-private`. روابط الصور مؤقتة وموقعة، ولا تجعل bucket عاماً.

**تنبيه:** هذا الربط السحابي مطبّق حالياً على قسم السيارات فقط. بقية الأقسام لا تزال محلية. لا تضع مفتاح `service_role` في متغير يبدأ بـ `NEXT_PUBLIC_` ولا تشاركه في المحادثة. لا تدخل بيانات عملاء حقيقية قبل اختبار صلاحيات الحساب والنسخ الاحتياطي.
 


## ARKAN GLOBAL command center

- تمت إضافة قسم «مركز القيادة الذكي / Global Command» إلى القائمة، ويجمع إشارات تشغيلية من السجلات المحملة حالياً.
- يكتشف مؤشرات للمراجعة مثل العقود المتأخرة، الحركات النقدية غير المصنفة، الحوادث المفتوحة، غياب فحص التسليم للعقود النشطة، المخالفات غير المحصلة، فروقات إغلاق الصندوق، واحتمال تداخل عقود السيارة.
- يعرض مسارات تشغيل موحدة قبل اعتماد العقد وعند التسليم والإرجاع والإغلاق اليومي، مع انتقال مباشر إلى القسم المعني.
- هذه الإشارات تنبيهية ولا تنفذ تغييرات مالية أو تعاقدية تلقائياً. يجب على المسؤول مراجعة السجل واتخاذ القرار.
- يعرض المركز بيانات مساحة العمل والفرع المحدد فقط؛ لا يثبت ذلك اكتمال المزامنة السحابية لجميع الأقسام.
- تبقى خدمات GPS الحي وWhatsApp API والدفع الإلكتروني والذكاء الاصطناعي الخارجي غير مفعلة حتى توفير مزوديها وبيانات الاعتماد السرية ومراجعة الخصوصية.


## ARKAN operations workspaces

- **Partners & Suppliers:** records for workshops, insurance/service providers, suppliers, contacts and payment terms.
- **Drivers & Delivery:** driver directory, licence expiry, availability and assigned delivery tasks.
- **Vehicle Marketplace:** internal vehicle-listing drafts with car, daily rate, channel and validity dates. This does not publish to external marketplaces automatically.
- **Customer Support:** customer requests, priority, status, assignee and resolution notes.
- These workspaces use the existing branch-scoped `arkan_records` store and its current RLS policies; no destructive schema migration is required. They inherit the same cloud/local limitations described above.

## تحديثات ARKAN المتقدمة

- **بوابة العميل:** افتح قسم «بوابة العملاء» من حساب إدارة الشركة وانسخ رابط الدعوة. يفتح العميل الرابط بصيغة `/portal?company=<company-id>`، ثم ينشئ حساباً أو يسجل الدخول ويرسل طلب ربط. يجب على المسؤول اختيار ملف العميل الصحيح والتحقق من الهوية والرخصة قبل اعتماد الطلب.
- **خصوصية البوابة:** تعرض البوابة حجوزات وعقود العميل المرتبطة بمعرّف سجل العميل فقط، عبر سياسة RLS. السجلات القديمة التي لا تحتوي `customer_id` لم يتم ربطها تلقائياً؛ بعض الأسماء قد تكون متكررة، ويجب ربطها يدوياً بعد التحقق. زر الحجز الإلكتروني يبقى معطلاً إلى أن يكتمل مسار الحجز الآمن والتحقق الكامل.
- **الأرشيف الإلكتروني:** تحفظ بيانات الوثيقة ومرفقات PDF والصور وملفات Office/CSV داخل bucket خاص `arkan-private`، بحد أقصى 10 ميغابايت للملف. الروابط الموقعة مؤقتة وليست روابط عامة.
- **الموظفون والعمولات:** ربط الموظف بالفرع وصلاحياته يتم عبر إدارة أعضاء الفرع. سجل العمولات يحفظ منفصلاً عن عضوية الموظف، ولا ينشئ دفعات تلقائية.
- **التسعير:** يعرض النظام اقتراحات سعرية استرشادية فقط. لا تتغير أسعار السيارات تلقائياً.
- **مساعد ARKAN:** يقدم مؤشرات وقواعد تحليلية محلية من بيانات النظام؛ لم يتم ربط نموذج ذكاء اصطناعي خارجي أو إرسال بيانات العملاء إلى خدمة خارجية.
- **واتساب:** مركز واتساب يفتح رسائل جاهزة للمراجعة والإرسال اليدوي. إرسال WhatsApp Business API الآلي غير مفعّل إلى حين إعداد مزود الخدمة وبيانات الاعتماد السرية على الخادم.
- **GPS:** قسم أجهزة التتبع يحتفظ ببيانات الجهاز والإحداثيات اليدوية ويفتح الموقع على الخريطة. التتبع الحي يحتاج مزود أجهزة وواجهة API معتمدة.
- **فحص التسليم والإرجاع:** فحص كل مرحلة مرتبط بعقد مسجل وسيارة وعميل العقد، ويتطلب قراءة عداد صحيحة. لا يسمح النظام بتسجيل الإرجاع قبل وجود فحص تسليم مطابق، أو بإدخال عداد إرجاع أقل من عداد التسليم. يعرض تقرير المقارنة فرق الكيلومترات ومستوى الوقود وملاحظات الأضرار، ويحفظ الصور والفيديو في التخزين الخاص. عند فشل حفظ الفحص تُزال الملفات التي رُفعت في المحاولة، وعند حذف سجل الفحص تُزال مرفقاته المرتبطة به. السجلات القديمة لم تُعدّل تلقائياً.
- **المالية:** التقارير تفصل العملات وتوحّد التسميات العربية الشائعة (مثل «شيكل» إلى ILS) دون تحويل أسعار صرف أو جمع عملات مختلفة. تُحسب الإيرادات من حركات القبض المؤكدة، والمصاريف التشغيلية من سجلات الصيانة والتأمين والترخيص/تكاليف السيارات؛ لا تُكرر مصروفاً واحداً في أكثر من قسم. حركات الصندوق ذات النوع غير الواضح تُستبعد من القبض والصرف والأرباح والديون، وتظهر في شاشة المالية لتصحيحها يدوياً. السجلات القديمة لم تُعدّل تلقائياً.

ملف سياسات البوابة والأرشيف: `supabase/customer_portal_archive_access.sql`. تم تطبيق سياسات RLS وتوسيع أنواع الملفات المسموحة في bucket الخاص مع الإبقاء على خصوصيته وحد 10 ميغابايت.

## 1) المتطلبات
- كمبيوتر Windows / macOS.
- تثبيت Node.js إصدار 20 أو أحدث من https://nodejs.org
- تثبيت VS Code اختياري.
- اتصال إنترنت لتنزيل الحزم.

## 2) تشغيل البرنامج على الكمبيوتر
1. فك ضغط `ARKAN_WEB_STARTER.zip`.
2. افتح المجلد `arkan-web-app` في VS Code.
3. افتح Terminal داخل المجلد.
4. نفّذ:

```bash
npm install
npm run dev
```

5. افتح هذا العنوان في Chrome أو Edge:

```text
http://localhost:3000
```

لإيقافه اضغط `Ctrl + C` في نافذة Terminal.

## 3) رفعه كرابط مؤقت على الإنترنت
1. اربط مستودع GitHub بالمشروع في https://vercel.com.
2. اختر إعدادات Next.js الافتراضية ثم Deploy.
3. استخدم رابط Vercel الذي يظهر بعد نجاح النشر.

نجاح البناء أو ظهور رابط عام لا يثبت أن تسجيل الدخول أو مزامنة البيانات أو الصلاحيات تعمل. لا تُدخل بيانات عملاء حقيقية في النسخة التجريبية.

## 4) إعداد قاعدة Supabase (تهيئة فقط؛ لا تفعّل التشغيل التجاري بعد)
1. أنشئ مشروعاً خاصاً في https://supabase.com.
2. خذ نسخة احتياطية أولاً إذا كان المشروع يحتوي بيانات.
3. افتح SQL Editor وشغّل `supabase/schema.sql` مرة واحدة لإنشاء الجداول والسياسات الأولية.
4. **بعد نجاح الخطوة السابقة، شغّل `supabase/production_upgrade.sql` أيضاً. لا تتجاوز هذه الخطوة.** ملف الترقية ينشئ دوال عضوية الشركة وإنشاء/استرجاع شركة المالك، ويستبدل سياسات العضوية العامة بسياسات تعتمد الأدوار. تشغيل `schema.sql` وحده يترك سياسات أولية أوسع من سياسات الترقية.
5. راجع نتائج SQL وتأكد من عدم وجود أخطاء قبل الانتقال للخطوة التالية.
6. من Project Settings → API انسخ Project URL و anon/public key فقط.
7. أنشئ ملف `.env.local` في جذر المشروع بناءً على `.env.example`، وأضف:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

8. أعد تشغيل التطبيق.

**مهم:** هذه الخطوات تهيئ قاعدة البيانات فقط. التطبيق الحالي لم يكتمل فيه تسجيل الدخول ولا إنشاء عضوية المالك من الواجهة ولا مزامنة السيارات مع جدول `cars`. لذلك لا تعتبر إضافة المفاتيح أو تشغيل SQL دليلاً على أن التطبيق أصبح سحابياً، ولا تستخدمه لتشغيل الشركة قبل تنفيذ واختبار الربط.

## 5) بيانات الشركة والأمان
- استخدم حساباً منفصلاً لكل موظف، ولا تشارك كلمة مرور واحدة.
- لا تنشئ عضويات الموظفين أو تغيّر أدوارهم من المتصفح بصلاحيات مرتفعة؛ يجب أن يتم ذلك من مسار موثوق.
- خزّن صور الهويات والعقود في Storage خاص (Private bucket) مع روابط مؤقتة.
- لا تضع `service_role` key في متغير يبدأ بـ `NEXT_PUBLIC_` أو في كود المتصفح أو مستودع GitHub.
- فعّل النسخ الاحتياطية واختبر استعادة البيانات.
- اختبر عزل الشركات وصلاحيات كل دور بحسابات تجريبية منفصلة قبل إدخال بيانات حقيقية.

## 6) مراحل التطوير المقترحة
1. إضافة تسجيل الدخول وإنشاء حساب المالك وربطه بالشركة.
2. ربط السيارات بقراءة/إضافة/تعديل/حذف آمنة في Supabase واختبارها من جهازين.
3. ربط العملاء والحجوزات والعقود ومنع تعارض مواعيد السيارات.
4. تطوير التسليم والاستلام وتصوير الأضرار والعقود PDF.
5. دفتر الصندوق والعملات وأسعار الصرف والتقارير المحاسبية.
6. الصلاحيات وسجل التدقيق والفروع.
7. ربط مزود GPS عبر API بعد اختيار الجهاز والمزود، ثم WhatsApp والتنبيهات وبوابة العملاء والتحليلات.

يجب أن تدعم واجهة النظام والعقود العربية والإنجليزية بالكامل، مع اتجاه RTL للعربية وLTR للإنجليزية.

- `app/globals.css`: التصميم المتجاوب.

## Server-side validation for cloud bookings and contracts

- The current web interface stores bookings and contracts in `arkan_records` (JSONB), not only in the legacy `bookings` and `contracts` tables.
- Apply `supabase/arkan_server_side_rental_validation.sql` after the unified cloud records, branch, and customer-compliance setup. It adds a database trigger that requires a linked customer and re-checks the customer's age, driving-licence duration/validity, and both identity-document images on every cloud booking/contract insert or update.
- This is additive and does not rewrite existing bookings or contracts. Older records without `customer_id` remain unchanged; edit and save each record only after matching it to the correct customer. Do not bulk-link by name because customer names may be duplicated.

## Database-level vehicle availability protection

- Apply `supabase/arkan_rental_availability.sql` after the unified cloud-records and branch setup.
- The database now rejects overlapping active bookings/contracts for the same vehicle, even when requests arrive from separate devices at nearly the same time.
- Existing records are not rewritten or deleted. Historical overlaps are not automatically changed; review them manually before relying on availability reports.
- Availability uses the vehicle identifiers in the saved car label (for example, plate and car number separated by ` - `).
